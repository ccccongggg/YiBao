## 四、核心技术事实（务必遵守）

### 设备与 USB
- USB VID `0x2E1A`，PID `0x4C04`
- 云台控制走**标准 UVC Camera Terminal（unit 1）**，selector `0x0D`（CT_PANTILT_ABSOLUTE_CONTROL），SET_CUR / GET_CUR，8 字节 = int32 小端 pan + int32 小端 tilt；**zoom 走 UVC ZOOM_ABSOLUTE（IAMCameraControl Zoom），范围 100-400（1x-4x 数字变焦），实测可用**
- 硬件极限：pan ±522000，tilt -324000 ~ +360000；**建议软件限位 pan ±360000，tilt ±270000**（度单位：pan ±145°，tilt -90°~+100°）
- 视频档位：720p/1080p@24-60fps、4K@24/25/30fps

### Windows 技术路线
1. **云台控制（已实测打通 2026-08-29）**：DirectShow `IAMCameraControl`（C 程序 `win-ptz\ptz_dshow.exe`）。系统 usbvideo.sys 自动映射 KSPROPERTY_CAMERACONTROL_PAN/TILT → UVC CT_PANTILT_ABSOLUTE_CONTROL，默认驱动即可用。**单位是度**（pan ±145°，tilt -90°~+100°，与 libusb 原始角秒值 ×3600 换算一致）。用法：`ptz_dshow.exe`（读）、`ptz_dshow.exe <pan> <tilt>`（写，自动限位）
2. **视频流**：FFmpeg DirectShow，`ffmpeg -f dshow -i video="Insta360 Link 2"`（dshow 枚举已确认设备名就叫 "Insta360 Link 2"）
3. 官方高级功能（AI 跟踪/变焦/手势）无 Windows SDK，需 UVC 扩展单元逆向或放弃（注意：zoom 或可试 IAMCameraControl Zoom 属性）
4. libusb 路线在 Windows 默认驱动下 `open failed`，已放弃（见上文红线说明）

### ⚠️ 三大坑（血泪经验）
1. **云台不动时先查视频流**：设备无人读流时处于隐私待机，云台命令会"假成功"。**控制前必须先开视频流**。
2. **关掉 AI Tracking**：相机自带追踪开启时会自己转，与手动控制打架。
3. **单视频消费者**：多个程序同时抢摄像头会掉线串流。

### 🚫 驱动红线
**绝对不要用 Zadig 给摄像头换 WinUSB 驱动**。换了后摄像头从系统 webcam 列表消失（Zoom/Chrome/FFmpeg 全打不开），现场极难恢复。libusb 用默认驱动即可控制 UVC 单元。

## 五、可以直接做的事

1. **Link2 Studio 综合控制平台（v2，主力，2026-08-29 实测 17/17 通过）**：
   - 路径 `win-ptz\link2_studio.py`，启动：`python win-ptz\link2_studio.py`，浏览器打开 `http://127.0.0.1:8899`

   - 功能：30fps canvas 实时画面（`/video.raw` 裸流 + 前端 fetch 解析）、按住持续移动（速度 10-180°/s）、平滑 goto、pan/tilt/zoom 滑块、**变焦 1x-4x**（zoom 100-400，IAMCameraControl Zoom，实测可用）、点击画面转向（按 FOV 换算）、预设位 CRUD（`studio_config.json` 持久化）、巡航模式、截图（`snapshots/`）、录像 MP4 H.264（帧 tee 到第二 ffmpeg，不占摄像头，`recordings/`）、720p/1080p 切换、完整 REST API（页内有文档面板）
   - 旧版 `ptz_server_win.py`（8787 端口）保留可用，但每命令重启进程较慢，建议用 Studio
2. 目标跟踪：Python + OpenCV（读 `/video.raw` 或直接 ffmpeg dshow）检测目标 → `/api/goto` 联动
3. 定时巡航（Studio 已有手动巡航，可加定时器）
